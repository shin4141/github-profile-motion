# Daily refresh rollout record

Reason: Shin requested his own current GitHub contribution data in the approved cat animation every day, plus a reusable low-setup path for other profile owners. Before this change, generator main was `9365916bab74fb6dd756aa2150a9a842284beda1` and the live profile used the fixed cat GIF from `af863aca4595b32e18e05fda19a2e3cbda385463`.

Impact: the new reusable workflow runs only when called from a profile repository. The caller supplies `contents: write` for its own repository; no cross-repository write token is needed. Real GraphQL capture, source/identity/date validation, approved two-scene rendering, GIF validation, and README URL/caption preparation happen before the caller commits and pushes the image and README together. The URL contains the generated GIF's hash to avoid retaining the old cached image. The checked-in cat and fox examples remain fixed historical examples, not the daily output. A fork owner must enable Actions if GitHub disabled them and must explicitly copy the starter into their profile repository.

Failure boundary: capture, permissions, missing images, invalid data, rendering or push failure leaves the prior **remote** GIF and README untouched; the Actions run fails visibly. No `--sample` fallback is used. A successful manual run proves the path once; the configured daily cron is not proof of a later scheduled success. GitHub can delay scheduled workflows and may disable inactive public repositories.

Rollback: in the calling profile repository, disable or remove the scheduled workflow first, then use a reviewed change to restore the prior fixed image URL/dated label and remove or retain the generated GIF as appropriate. Do not reset a later main. If this generator needs rollback, compare with source main `9365916` and revert only the reusable-workflow/updater additions through a reviewed change; preserve fixed examples and subsequent unrelated changes. The caller's last successful GIF stays available until a new reviewed profile change replaces it.
