# Daily profile GIF in your own README

1. In your special `YOUR_LOGIN/YOUR_LOGIN` profile repository, copy `starter/update-profile-motion.yml` to `.github/workflows/update-profile-motion.yml`, and copy `starter/profile-motion.json` plus `starter/your-icon.png` to its root. Change `username` in the JSON to your GitHub login; the included fox icon and GitHub-like green grid work immediately. Replace `icon` with your own image filename and edit `accent` / `glow` or their `_dark` variants (`#RRGGBB`) whenever you like. One image is enough; `sleep_icon` and `wake_icon` are optional extra poses.
2. Add the short block in [`README-snippet.md`](README-snippet.md) where the animation should appear in your profile `README.md`. Keep both comment markers exactly once. The first run replaces the pending message with a dated label and a theme-aware `<picture>` using two hash-versioned GIF URLs.
3. Enable Actions in a fork if GitHub has disabled them. On your profile repository's Actions tab, manually run **Daily profile animation** on the default branch. Inspect the run and the resulting profile commit before relying on the daily schedule. Each run captures 365 dated days; the example runs at 03:17 UTC. Change the cron line if desired.

The caller's built-in `GITHUB_TOKEN` needs `contents: write` in the workflow to commit its own GIF and README; no cross-repository PAT or new secret is required for the public contribution-calendar path. The reusable generator only reads the GitHub GraphQL `contributionsCollection`, using that token as `GH_TOKEN`. GitHub's [workflow permissions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#defining-access-for-the-github_token-scopes) and [scheduled-run behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) apply: schedules can be late or disabled in inactive public repositories, and forked repositories may need Actions enabled manually. Private/internal contributions require additional access and are not covered by this public-data starter.

Failed capture, missing icon, invalid data, or either GIF failing make the workflow fail **before any commit or push**; your previous public images and README stay in place. There is no synthetic fallback. The Actions run and its summary show the last attempted result; the profile label shows the last successful capture. GitHub's native contribution graph is never altered. For a stable renderer, replace `@main` in the caller workflow with a reviewed full commit SHA and set `generator_ref` to the same SHA under `with:`.
